4.1 Experimental Settings

Benchmarks

  • AVUT [5]：面向音频中心的视频理解，覆盖事件定位、对象匹配及信息提取等任务。
  • WorldSense [4]：覆盖现实场景中的音视频感知与推理，检验联合模态理解能力。
  • Video-MME [2]：覆盖短、中、长视频的多领域选择题评测，检验时长与内容泛化。
  • MVBench [1]：通过二十类任务评测动作、事件顺序及时间关系理解。
  • LongVideoBench [3]：评测长视频中的指代定位与细节推理，并提供视频与字幕交错输入。
  • DailyOmni [6]：使用日常场景音视频选择题评测跨模态时间对齐、事件理解与推理。

Comparison Methods

  • Full Tokens（Qwen2.5-Omni [11] · 代码）：完整保留共同预处理后的输入 token，作为准确率与成本基准。
  • Random（参考论文 [13] · 参考代码）：对音视频 token 分别随机采样，作为无评分压缩对照。
  • FastV-AV（论文 [7] · 代码）：使用语言模型浅层注意力选择 token，本计划扩展到音视频两种模态。
  • FastVID-AV（论文 [10] · 代码）：结合关键帧选择与时空冗余压缩视频，音频采用统一均匀采样。
  • DyCoke-TTM-AV（论文 [8] · 代码）：将时间 token 合并模块 TTM 应用于音频和视频。
  • OmniZip（论文 [13] · 代码）：以音频显著性引导视频预算分配，并结合音频锚点合并与时空压缩。
  • OmniSelect（论文 [14] · 代码）：使用 AudioCLIP 判断问题的模态偏好，动态选择音视频压缩策略。
  • OmniPack（论文 [15] · 代码）：结合进入语言模型前的选择合并与模型内部剪枝，进行两阶段压缩。
  • FRO (Ours)（本地代码）：结合跨视频证据与时间新颖性评分，在第 2 层特征评分后选择输入 token。

FLOPs Calculation

固定参考输入与统计口径

项目计算设置
参考序列N=32,256；音视频 32,000、文本 256；两路等长。FRO 两档主序列为 14,656 / 11,456；其他方法按对应预算反算长度。
生成预算R = 100 个解码步用于 FLOPs 口径；实际选择题仍使用计划中的最多 32 个输出 token。
矩阵运算1 MAC = 2 FLOPs；使用 GQA 的真实 K/V 维度与三投影 SwiGLU；注意力按稠密 N×N 矩阵乘法统计。
未计项目 δ辅助模型 AudioCLIP、其他选择/聚类/合并矩阵及逐元素算子另行统计；共同音视频编码器、LM head、softmax、归一化与排序不在本参考表中。

计算公式

d：隐藏维度；m：FFN 中间维度；k：K/V 总维度；L：Transformer 层数。
A = 4d² + 4dk + 6dm
P(n) = An + 4dn²
D(n) = RA + 4d[Rn + R(R+1)/2]
C = Σℓ=1…L [P(nℓ) + D(nℓ)]
